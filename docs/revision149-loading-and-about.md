# Revision 0.9.149: hosting audit, startup catalogue and About panel

## Live hosting audit

The read-only audit on 21 October 2026 found that the public website was serving release 0.9.143. HTTP and the bare domain redirected to https://www.neurovascularatlas.com/. The homepage, JavaScript, stylesheet, catalogue and sampled initial model files were served with gzip encoding. Sampled successful responses had `Cache-Control: max-age=600`. The live robots.txt and sitemap.xml returned 404; both files are already generated by the newer build and require deployment to become available.

The response headers identify GitHub Pages delivery. Its response headers are controlled by GitHub Pages. The included Nginx configuration applies to Docker/Nginx installations, not to GitHub Pages. No DNS, hosting-account or live source settings were changed.

See revision149-live-hosting.json for the measured responses and timings. Those timings are individual HTTP requests from the test environment, not mobile browser load times. The mobile PageSpeed API request returned HTTP 429, so no mobile Lighthouse score or Core Web Vitals result is claimed. The separate status file records this limitation.

To repeat the read-only audit after deployment, run `npm run web:audit`. The audit writes its report to docs/revision149-live-hosting.json.

## Startup catalogue

The browser now loads a content-addressed viewer catalogue instead of the full authoring manifest. The full manifest remains available at anatomy/manifest.json and continues to drive anatomical validation and DSA data generation.

The startup catalogue retains every displayed description, alias, relationship, landmark, primary surface anchor, geometry binding, geometry dependency and preset input. Authoring course specifications, course-authoring control points, audit history and other metadata not used by the current viewer stay in the full manifest. No descriptions are deferred, and opening a structure does not require another text request.

The build writes the catalogue to anatomy/viewer/catalogue-<content-hash>.json, records its release and digest in src/viewerCatalogueAsset.json, and gives the HTML preload exactly the same URL used by the loader. This allows safe cache reuse without changing the catalogue at an existing content-addressed URL. Nginx serves this directory with immutable caching; GitHub Pages retains its own cache policy.

The catalogue generation step is part of build-anatomy.sh and therefore runs for normal builds and the existing installation/update procedure. No dependencies were added. All five model files remain unchanged.

## Measurement

For the same anatomy, the full compact catalogue is 6.71 MB and the startup catalogue is 2.25 MB. Level-9 gzip in the controlled benchmark is approximately 1.40 MB versus 0.34 MB. This is approximately 66% less uncompressed catalogue data and 75% less gzip data. These percentages describe the catalogue, not the entire application's loading time. Large model downloads and geometry preparation remain separate costs.

See revision149-catalogue-validation.json for exact bytes and the 25-sample Node parsing microbenchmark. These parsing times are not user-device or browser loading times.

The application records `atlas-catalogue-load` and `atlas-startup` performance measures in a WebGL-capable browser. They cover catalogue loading/parsing and boot-to-primary-model readiness respectively. They are local browser performance entries; they do not send analytics or telemetry.

## About panel

The existing panel now describes its anatomical scope, credits Jeremy Lynch and Sean McIlhone, states Jeremy Lynch's clinical role at King's College Hospital and editorial role for Neurointervention, and describes the educational applications in angiography, aneurysm treatment, stroke thrombectomy and embolisation. The wording contains no awards, rankings, claims of superiority or clinical outcome claims. Existing reference and software credits remain.

## Validation and delivery

The production build includes TypeScript and anatomy validation. `npm run web:validate` compares the full and viewer catalogues across every structure's descriptions, aliases, landmarks, anchors, focus geometry and dependencies, plus search results, vessel counts, geometry groups and all 15 DSA preset/side combinations. It checks loader URL selection, cache modes, full-manifest access and failure handling. The updated orbital flow validation also passes all 28 courses.

The release ZIP follows the existing source-package format. `npm ci` and `npm run build` generate the deployable dist directory. The live website was not updated as part of this release.
